# ArchDev plugins

Generated by `tools/plugin-gen` from `catalog/archdev.json` (version 0.49.2). Do not edit files under `plugins/` or the marketplace files by hand; change the catalog and run `npm run build` in `tools/plugin-gen`.

Each plugin bundles the ArchDev skills, the remote MCP server (`https://archdev.ai/api/v1/mcp`, OAuth sign-in) and, where the CLI supports the harness, session hooks. The hooks run `archdev repo hook` from PATH. When the CLI is not installed, Claude Code and Codex run a bundled shell script (`hooks/archdev-nudge.sh`; no network, no dependencies beyond POSIX tools) that tells the agent which ArchDev MCP tool to call for what just happened: session start, each later user message, commits, pushes, pull request create, update and merge, and (Claude Code only) plan files. It never installs anything, and with the CLI on PATH the hooks run the CLI exactly as before. Grok and Pi print a short note at session start telling the agent to offer the user the CLI install (nothing is installed without the user's approval); their other hooks do nothing without the CLI. Claude Code and Grok read the MCP server URL from `ARCHDEV_MCP_URL` when it is set. Hook commands are POSIX shell: they run on macOS and Linux, and on Windows only where the harness runs hooks through Git Bash (Claude Code). Pi's hooks are JavaScript and run everywhere.

The plugin is one of four independent ways to install ArchDev:

1. Plugin: skills, MCP and hooks together (below).
2. Skills only: `npx skills add ArchAstro/archdev`.
3. Hooks only: `archdev repo hook setup` from the ArchDev CLI.
4. MCP only: add `https://archdev.ai/api/v1/mcp` as a remote MCP server.

Install hooks through either the plugin or `archdev repo hook setup` for a given harness, not both: both copies would run and report each event twice.

Installing from the `v0.49.2` tag pins every file to that release.

### Claude Code

```sh
claude plugin marketplace add ArchAstro/archdev#v0.49.2
claude plugin install archdev@archdev
```

Sign in to the MCP server with `/mcp`.

### Codex

```sh
codex plugin marketplace add ArchAstro/archdev --ref v0.49.2
codex plugin add archdev@archdev
```

Codex runs plugin hooks only after you trust them in `/hooks`. Sign in to the MCP server when Codex asks.

### GitHub Copilot CLI / VS Code

```sh
copilot plugin marketplace add ArchAstro/archdev
copilot plugin install archdev@archdev
```

VS Code: add `"ArchAstro/archdev"` to `chat.plugins.marketplaces`. The Copilot cloud agent cannot use OAuth MCP servers.

No hooks yet: archdev repo hook has no --harness copilot handler for Copilot's camelCase payloads and output contract.

### Cursor

Add `https://github.com/ArchAstro/archdev` as a team marketplace, or copy `plugins/cursor` to `~/.cursor/plugins/local/archdev`.

No hooks yet: archdev repo hook has no --harness cursor handler for Cursor's payloads and output contract.

### Antigravity

```sh
git clone --depth 1 --branch v0.49.2 https://github.com/ArchAstro/archdev.git
agy plugin install ./archdev/plugins/antigravity
```

Authenticate the MCP server in Settings > Customizations.

No hooks yet: Antigravity has no SessionStart or UserPromptSubmit event and reads a named-hook file shape; the CLI's gemini handler targets neither.

### Grok Build

```sh
grok plugin install ArchAstro/archdev@v0.49.2#plugins/grok --trust
```

Without `--trust`, Grok asks before running the plugin's hooks.

### OpenCode

Add `"plugin": ["@archastro/archdev-opencode@0.49.2"]` to `opencode.json`. Sign in with `opencode mcp auth archdev`.

No hooks yet: archdev repo hook has no --harness opencode handler for OpenCode plugin events.

### Pi

```sh
pi install git:github.com/ArchAstro/archdev@v0.49.2
```

Pi has no MCP client. Reload Pi after installing.
